# Iteration evidence

For visual work, collect and preserve the original revision, captures and conditions before any task source edits. After the root creates each source commit, dispatch an existing qualified visual or operations specialist to collect evidence on that actual commit before independent review, acceptance or push. Compare each commit with both that baseline and the preceding commit under recorded conditions. Keep screenshot paths and observations from real interaction; capture video when the host supports it. Record unavailable comparisons as Unknown with the reason. The last PR is not a replacement for the original task baseline.

For optimization, establish the objective and measurable target before work. Before any task source edits, collect and preserve the original revision, measurements and conditions. After the root creates each source commit, dispatch a qualified existing operations or validation specialist to measure that actual commit before independent review, acceptance or push. Measure the relevant workload before edits and compare each commit against both the original and preceding measurements. Record the environment, workload, cache state and run conditions; account for cold and warm runs and noise. Check correctness, user experience and security alongside performance. Report missing measurements and failed runs honestly. Mark missing required evidence Unknown with a concrete reason and a blocker when the target requires it.

For both workflows, the first comparison uses the original revision as the preceding revision; advance the preceding revision after each commit while preserving the original. Precommit checks do not replace evidence on the actual commit. Associate reports and artifacts with the commit SHA outside the source commit as needed and point persisted state and handoff to them, avoiding recursive evidence-only commits.

In branch state mode, push `holyagent/state` after each Assignment close and merge and before the turn ends. Replace the current status and open-items requirement in the Intent after a merge, a new blocker and before the final response, including PR and CI state, the next action, residuals and untried real-service checks. The recorded state should let another harness resume; the shared handoff command reads it without mutation.
