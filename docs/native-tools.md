# Native HolyAgent tools

On the verified Pi 1.5.0 and pi-subagents 0.23.2 host combination, launch the root explicitly with `--holyagent-native-root`. The flag has no default; a child loader does not inherit it. Native tools remain unavailable unless both the user's and the merged project's HolyAgent configurations are successfully read with `pi.enable` enabled. A disabled or unreadable configuration fails closed. Reload, compaction, disable and shutdown revoke current calls, and a stale registered tool checks the capability again on execution. Pi retains hidden registry metadata after disable because it offers no unregister API. Unknown Pi versions do not activate these tools.

The registered `holyagent_*` operations call the private `@holyagent/core` Effect APIs directly with strict shared schemas. No HolyAgent CLI process, argv proxy or CLI output parser is involved. The host sets the working directory, environment, authorization callback and first-pass prompt assets; a model cannot supply authority. Tool output preserves exact structured data in `details` and escapes terminal controls in text. Cancelling interrupts the Effect. State persistence, its commit and required post-state artifacts finish under the lock before interruption completes. A cancelled call may already have completed; inspect status before retrying. A process crash can leave a partially completed multi-file transition.

Intent and Assignment operations, reports, plan, status, reconcile, handoff, migration and state-mode reads are available. Changing state mode through the native tool is refused: it changes Git configuration and an equivalent approval mechanism for every provider is not established. Core now offers typed setup, doctor and VCS operations to trusted hosts. Pi does not expose them: its root capability does not establish equivalent process, filesystem or GitHub authorization; hooks are host lifecycle interfaces, raw `rg`/`fd` are passthroughs, and the browser server is a long-lived stdio process. Their existing CLI or host integrations remain available. The explicit root flag grants role authority; it does not grant approval for unrelated privileged effects.

With a normal or fast routing profile, direct `Agent`/`agent` calls require an exact authenticated provider/model registry entry. Both `SubagentWorkflow` aliases are refused because the pinned upstream workflow resolver can substitute another provider. Registry presence does not prove account entitlement. Without a profile, existing workflow behavior is retained.

The flag and loader boundary do not secure shell commands a specialist can run, establish a cross-host principal, or prove that an account is entitled to a model. Other Pi and pi-subagents versions need their flag isolation and tool-call contracts verified before enabling the native capability. Claude native tools remain unsupported until its host supplies trusted per-call authority; its CLI remains available.
