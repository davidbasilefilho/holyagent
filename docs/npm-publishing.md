# npm publishing

The public package is `holyagent`, packed from `packages/integrations/pi/dist`; the workspace root is private. Its Pi host dependencies are peers supplied by the user's Pi installation. The bundled runtime does not require publishing the internal workspaces.

Before publication, an authorized administrator must create the GitHub environment `npm` and restrict deployment branches to the protected heads `main` and `dev`; verify that the corresponding branch rulesets apply and that bypass permissions are appropriate. The environment name in a workflow does not itself restrict branches. Configure the npm trusted publisher for `holyagent` with owner `davidbasilefilho`, repository `holyagent`, caller workflow `publish.yml`, and environment `npm`. Verify the actual GitHub and npm settings before publishing; this repository does not configure them. Grant no npm token secret. The `publish.yml` caller grants OIDC only to the stable and dev calls, which grant it only to their npm jobs.

Branch pushes run validation first. The stable and dev workflows pack the public Pi distribution with `bun pm pack`, validate its repository metadata against the provenance repository, publish that tarball to npm using trusted publishing, then pass the same published tarball to a dependent GitHub release job. Protected main publishes under `latest`; protected dev publishes under `dev` with the commit UTC timestamp and short SHA in its version. Other branches validate but do not publish. Pull requests have no publication permissions. An npm failure prevents a new GitHub release; a later GitHub release failure may leave an npm version without a GitHub release, so investigate before retrying.

Before npm publication, the helper checks the exact GitHub tag against the intended commit. An absent or matching tag permits publication; a conflict or lookup failure stops it. The release action checks again afterward for races. A race or subsequent release failure can still leave an immutable npm version without its GitHub release; investigate and resolve it through an authorized manual process.

A rerun publishes only when the registry reports the packed version missing. Every existing version is rejected, even if its identity and integrity match: trusted provenance cannot currently be established. This also prevents automatic reruns after npm succeeds but the GitHub release fails, including when a channel has moved to a newer version. Malformed or failed registry lookups fail closed. The helper never repairs dist-tags and has no token fallback.
