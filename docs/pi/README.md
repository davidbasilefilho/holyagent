# Pi coding agent: the plan for the HolyAgent Pi integration

**Status: planned for 0.3.0. Nothing on these pages is shipped.** HolyAgent 0.2.x supports Claude Code only. These pages state the plan the maintainer has decided for the Pi integration in 0.3.0, with the research it rests on. Where a page says "will" or "is planned", the code does not exist yet; the maintainer implements it in eleven open 0.3.0 Intents: the T3 Code Intent and the install-scope Intent joined the nine of the first plan (another, which would have added an auto-mode gate, was closed; see [auto-mode.md](auto-mode.md)).

The research is based on Pi's official docs and source code and on the third-party packages named on each page. Nothing was installed and no Pi code was written. Pi facts were read at Pi 1.4.0 unless a page says otherwise; the version the plan pins is 1.5.0 (see [Version risk](#version-risk)).

## Summary

Pi is a minimal terminal coding harness. It gives the model four tools by default (`read`, `bash`, `edit`, `write`), and it is customised through TypeScript extensions, skills, prompt templates, themes and installable packages ([README](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/README.md), [index.md L1-L8](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/index.md#L1-L8), [settings.md L42](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L42)). It runs interactively, in print mode, as a JSONL event stream, as an RPC child process, or embedded through a TypeScript SDK ([cli-integration.md L9-L18](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli-integration.md#L9-L18)). It deliberately has no built-in permission system and no sandbox: tools run with the OS permissions of the Pi process, and approval is something an extension builds on the `tool_call` event ([security.md L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L3), [README L88-L90](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/README.md#L88-L90)). Sub-agents and plan mode are not built in either; a sub-agent example spawns separate `pi` processes ([subagent/index.ts L298](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/index.ts#L298)). The nearest analogue of Claude Code dynamic workflows is the built-in `codemode` tool, a QuickJS sandbox in which the model writes JavaScript that calls other tools ([codemode.md L1-L8](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/codemode.md#L1-L8)). Pi has been moving quickly (see "Version risk" below), so HolyAgent pins an exact Pi version, 1.5.0.

## Which project "Pi" is

Pi is Mario Zechner's coding agent, now maintained under the Earendil Works organisation. The brief's guess (`badlogic/pi-mono`, `@mariozechner/pi-coding-agent`) is the old name of the same project:

- Official site and docs: [pi.dev](https://pi.dev) and [pi.dev/docs/latest](https://pi.dev/docs/latest). The root README links both ([README](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/README.md)).
- Official repository: [github.com/earendil-works/pi](https://github.com/earendil-works/pi). The old `badlogic/pi-mono` raw URL serves a `packages/coding-agent/package.json` that is already named `@earendil-works/pi-coding-agent` ([raw file via the old URL](https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/coding-agent/package.json)).
- Current npm package: `@earendil-works/pi-coding-agent`. The notes were read at `1.4.0`, published 2026-10-21; the latest is now `1.5.0`, published 2026-11-02 ([GitHub releases](https://github.com/earendil-works/pi/releases), [npm](https://www.npmjs.com/package/@earendil-works/pi-coding-agent)), and is the version the plan pins. The `1.4.0` date is the npm registry time (the changelog heading agrees: [CHANGELOG.md L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L3)), author "Mario Zechner", MIT, repository `earendil-works/pi` ([npm registry metadata](https://registry.npmjs.org/@earendil-works/pi-coding-agent)).
- Legacy npm package: `@mariozechner/pi-coding-agent` stopped at `0.73.1` and is deprecated with the message "please use @earendil-works/pi-coding-agent instead going forward" ([npm registry metadata](https://registry.npmjs.org/@mariozechner/pi-coding-agent)). The `v0.73.1` git tag is commit `781152fc24841dc54b22284514604048ebe5e2c9` ([ref list](https://github.com/earendil-works/pi.git/info/refs?service=git-upload-pack)). Do not rely on old docs: they differ materially (for example the 0.73.1 README says "No MCP." and "No permission popups." in its philosophy section, [0.73.1 README L470-L474](https://github.com/earendil-works/pi/blob/781152fc24841dc54b22284514604048ebe5e2c9/packages/coding-agent/README.md#L470-L474), whereas built-in MCP and codemode arrived in 0.99.0, see [CHANGELOG.md L440](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L440)).

### Version risk

Pi released 1.0.1 on 2026-10-03 and 1.4.0 on 2026-10-21, roughly weekly minor releases ([CHANGELOG.md L3, L280](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L3), [npm registry metadata](https://registry.npmjs.org/@earendil-works/pi-coding-agent)). The 1.4.0 changelog alone adds codemode wiring fixes, a models-configuration reference and classifier image input ([CHANGELOG.md L3-L50](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L3-L50)). The research found no statement in the 1.5.0 release notes that contradicts the 1.4.0 facts on these pages, but the pages were not re-read against 1.5.0; the fixtures recorded for the pin are what catches a difference ([installation.md](installation.md#the-pin)).

Pi 1.5.0 (2026-11-02) changes, from its [release notes](https://github.com/earendil-works/pi/releases), the points the plan touches:

- Extension tool-argument validation now runs on `@earendil-works/pi-schema` (breaking). TypeBox-only features (`Type.Refine`, `BigInt`, codecs) no longer apply; the `Type`, `Static` and `TSchema` imports still work. `pi.exec` gained `maxBuffer` and `truncated`.
- Packages gained `pi.changelogPath`. The package docs say the host modules (`pi-ai`, `pi-agent-core`, `pi-coding-agent`, `pi-tui`, `typebox`) go in `peerDependencies` with a `"*"` range.
- The model catalog moved to models.dev v2. The Kimi provider ids are unchanged, but the default model of `moonshotai` and others changed after 1.4.0 (now Kimi K2.7 Code). The Kimi docs were not read for this.
- Codemode: no change listed; `PI_CODEMODE_MAX_WORKERS` still defaults to 2.
- Added `PI_SELF_UPDATE_COMMAND`; MCP OAuth defaults changed.

The `pi-durable` package is marked experimental ([durable README](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/durable/README.md)).

## Top findings and gaps

1. **Pi has no native approval mechanism, so 0.3.0 runs with full access.** The only gate is an extension's `tool_call` handler returning `{ block: true }`. The maintainer decided against an auto-mode gate; see [approval.md](approval.md) and [auto-mode.md](auto-mode.md).
2. **Pi runs on Node; Bun is used only as its package installer.** Docs show the `pi.dev/install.sh` installer, `npm install -g --ignore-scripts` and Nix, and the CLI shebang is `node`. Bun is not an officially documented install route; the plan uses it only as Pi's `npmCommand`. See [installation.md](installation.md).
3. **There is no resumable workflow engine in Pi.** `codemode` runs model-written JS with no `agent()` primitive and at most two workers per process by default. The plan runs workflows through `@tintinweb/pi-subagents`, whose `SubagentWorkflow` tool claims to run Claude Code workflow scripts unchanged. See [orchestration.md](orchestration.md).
4. **Kimi caches exact prefixes.** Prompt caching on the planned provider depends on a byte-stable prefix and one model and effort per session, not on Pi's retention switch. See [caching-and-subagents.md](caching-and-subagents.md#cache-target).
5. **Moonshot has no K3.1-specific prompting guide.** The planned Kimi K3.1 instruction set follows the general prompt best-practice guide, the K3.1 Pro quickstart and the agent-setup guide. See [providers.md](providers.md#instructions-for-kimi-k31).
6. **The open points are marked where they sit.** They include the cache behaviour of Billion Context on Kimi, whether the process and subagent tools can be called from codemode scripts, the per-effort cost of `max` against `high`, and the built-in provider's API type ([providers.md](providers.md#kimi-for-coding-global)).
7. **T3 Code already runs Pi, and the plan builds on it.** T3 runs the user's Pi through `pi --mode rpc` and injects its own tools, keeping the HTML, preview and device ones and deactivating the rest, orchestration included; it has no computer use for Pi, so HolyAgent adds Cua Driver through the extension that bundles it. The T3 specifics still to verify are listed in [t3-code.md](t3-code.md#to-verify).
