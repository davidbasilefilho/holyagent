# Pi approval and permissions

Pi 1.4.0, commit `4a080252f06caf63a525d7873c5d94d3c23887e0`. "Inference:" marks my own conclusions.

## Pi deliberately has no native approval mechanism

- "Pi can read, change, and execute files with the permissions of the account that started it, and it does not ask for approval before every tool call" ([security.md L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L3)). The quickstart and usage pages repeat it: "It does not ask before every tool call" ([quickstart.md L68](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/quickstart.md#L68), [usage.md L27](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/usage.md#L27)).
- "Pi does not include a built-in permission system for restricting filesystem, process, network, or credential access" ([README L88-L90](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/README.md#L88-L90)).
- The security policy lists lack of a sandbox as out of scope: "the Pi coding agent intentionally does not have a sandbox" ([SECURITY.md L50](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/SECURITY.md#L50)); see also [security.md L99](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L99).
- Philosophy, from the 0.73.1 README (the 1.4.0 README no longer carries this section): "No permission popups. Run in a container, or build your own confirmation flow with extensions" ([0.73.1 README L474](https://github.com/earendil-works/pi/blob/781152fc24841dc54b22284514604048ebe5e2c9/packages/coding-agent/README.md#L474)).
- Pi's recommended safety posture is isolation (Docker, Docker Sandboxes, OpenShell, or the Gondolin micro-VM extension), not approval prompts ([containerization.md L7-L14](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/containerization.md#L7-L14)).

What looks like approval but is not: **project trust**. It decides which project resources load (settings, `.pi/extensions`, MCP config, skills); it "does not limit what tool calls can access or affect" ([security.md L27-L33](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L27-L33)). The `project_trust` event is the only place with a three-valued answer (`yes`, `no`, `undecided`), and `undecided` just falls through to Pi's built-in trust prompt ([types.ts L700-L710](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L700-L710), [project-trust.ts L1-L60](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/project-trust.ts#L1-L60)). **Tool calls have no such `undecided` result.**

## What extensions can intercept

### `tool_call`: inspect, mutate, block

- Fired for every tool call after the model produces it and before the tool runs. The event has `toolName`, `toolCallId`, `input` and optional `parentToolCallId` ([types.ts L1193-L1265](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1193-L1265)). Built-in tools are `read`, `bash`, `powershell`, `edit`, `write`, `grep`, `find`, `ls` ([cli.md L140-L149](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L140-L149)).
- The only result type is `{ block?: boolean; reason?: string; terminate?: boolean }`. To change arguments, mutate `event.input` in place ([types.ts L1454-L1463](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1454-L1463), [extensions.md L218](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L218)). Later handlers see earlier mutations ([extensions.md L208](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L208)).
- Handlers run in order; the first one that returns `block: true` ends the dispatch ([runner.ts L1249-L1268](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/runner.ts#L1249-L1268)).
- **Fail-safe on errors:** "A `tool_call` handler failure blocks the tool as a fail-safe" ([extensions.md L375](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L375)). In code, `_beforeToolCall` re-throws an `Error` instance unchanged and wraps only non-`Error` throws as "Extension failed, blocking execution: ..." ([agent-session.ts L658-L681](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/agent-session.ts#L658-L681)). The docs ask gate authors to "fail closed when their safety decision cannot be made" ([extensions.md L214](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L214)).
- **Coverage:** extension tools, MCP tools and nested calls made from codemode scripts or `ctx.executeTool()` all go through the same pipeline; nested calls carry `parentToolCallId` ([mcp.md L252](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/mcp.md#L252), [extensions.md L261](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L261)).
- **Not covered:** the user's own `!cmd` / `!!cmd` shell commands use a separate `user_bash` event ([extensions.md L240](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L240)). Code inside extensions (for example `pi.exec()`) is trusted and not routed through `tool_call` (Inference: no document says it is). Anything a permitted `bash` command spawns is outside Pi's view.
- **Concurrency:** tool calls from one assistant message can run in parallel, so gates must be safe under concurrent invocation ([extensions.md L236-L238](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L236-L238)). Pi 1.4.0 fixed concurrent `select`/`confirm`/`input` dialogs replacing each other ([CHANGELOG.md L38](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L38)).
- Blocking can also stop the agent loop: `terminate: true` has effect only if every finalized tool result in the batch sets it ([types.ts L1454-L1463](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1454-L1463)).

### UI confirmation dialogs

- `ctx.ui.confirm(title, message, opts)` returns a boolean; `ctx.ui.select(title, options, opts)` and `ctx.ui.input()` return `string | undefined`; `opts` accepts an `AbortSignal` and a `timeout` in ms ([types.ts L114-L119, L149-L160](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L114-L160)).
- Availability by mode: `ctx.hasUI` is true in the TUI and RPC, false in JSON and print mode ([types.ts L323-L331](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L323-L331), [extensions.md L363-L366](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L363-L366)).
- In RPC mode, dialogs become `extension_ui_request` records on stdout that block until the client replies with `extension_ui_response` carrying the same `id`; a timeout auto-resolves on the agent side; dismissal gives `false` for confirm and `undefined` for select/input ([rpc-extension-ui.md L5-L10, L48-L63, L186-L191](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/rpc-extension-ui.md#L5-L10)). So a HolyAgent host driving Pi over RPC can answer approvals itself, or relay them to a human.
- Working references: the official permission gate regex-matches `rm -rf`, `sudo`, `chmod/chown 777` in `bash` input, asks with `ctx.ui.select`, and when `!ctx.hasUI` blocks with "Dangerous command blocked (no UI for confirmation)" ([permission-gate.ts L13-L33](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/permission-gate.ts#L13-L33)); a path guard blocks `write`/`edit` to `.env`, `.git/`, `node_modules/` ([protected-paths.ts](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/protected-paths.ts)); the docs also show a gate that uses MCP-style tool annotations to decide when to ask ([extensions.md L279-L291](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L279-L291)).

### Other levers that are not approval

- Tool availability: `--tools` allowlist, `--exclude-tools`, `--no-tools`, `defaultTools`, `pi.setActiveTools()` ([cli.md L119-L125](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L119-L125), [settings.md L42](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L42)). The CLI docs show `pi --tools read,grep,find,ls --print "Review this project"` ([cli.md L114](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L114)); Inference: that is effectively a read-only session, since none of those tools writes (the docs do not call it read-only).
- Replacing built-in tools or sandboxing bash: the sandbox example overrides `bash` with OS-level sandboxing and notes that `bash` could instead be sandboxed "via `tool_call` input mutation without replacing the tool" ([sandbox/index.ts L1-L12](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/sandbox/index.ts#L1-L12)). The `bash` tool factory takes a `spawnHook` ([environment-variables.md L51-L61](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/environment-variables.md#L51-L61)).
- Whole-process isolation per [containerization.md](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/containerization.md).

## Decision matrix of what a Pi extension can answer for a tool call

| Wanted outcome             | Pi mechanism                                                    | Notes                                                           |
| -------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| Allow                      | return `undefined` (or no `block`) from `tool_call`             | default behaviour when no handler blocks                        |
| Deny                       | `{ block: true, reason }`                                       | `reason` text is the extension's                                |
| Allow with changes         | mutate `event.input`                                            | later handlers see the change                                   |
| Ask a human                | `ctx.ui.confirm/select` inside the handler, then allow or block | TUI and RPC only; timeout/dismiss yields `false` or `undefined` |
| "Undecided, let Pi decide" | **not available**                                               | Pi has no native tool approval to delegate to                   |
| Headless (print/JSON)      | no UI                                                           | the official gate blocks                                        |

## Inference for HolyAgent

- Inference: "undecided goes to Pi's native approval" cannot be implemented literally for tool calls, because Pi has no native approval. The faithful mapping is: undecided becomes an extension-driven `ctx.ui.confirm` (interactive TUI, or the host over RPC), and where no UI exists (print/JSON), undecided becomes a block, which matches the official gate's fail-closed pattern.
- Inference: "off means full access" is Pi's default behaviour (no gate loaded), so `off` is simply "do not load the HolyAgent gate extension" ([security.md L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L3)).
- Sourced: project `.pi/extensions` load only after trust is granted, and declining trust skips them ([security.md L35-L55](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L35-L55)); `-e/--extension` loads an extension from a CLI path ([cli.md L194](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L194)). Inference: a project-level gate would therefore be skipped when trust is declined, which fails open, while an explicit `-e` gate does not depend on the project folder, so load it explicitly. Also a different extension loaded earlier could allow-and-mutate before HolyAgent's handler runs; handlers run in load order ([extensions.md L197](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L197)).
