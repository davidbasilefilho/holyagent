# What a HolyAgent auto mode on Pi would require

Pi 1.4.0, commit `4a080252f06caf63a525d7873c5d94d3c23887e0`. The requirements are the ones given in the research brief. For each, the Pi mechanism that could support it is named, with a status: **Supported** (Pi documents a mechanism that does it), **Partial** (needs extension discipline or has a gap), or **Unsupported** (nothing in Pi does it). "Inference:" marks design reasoning that is mine, not Pi's. Background: Pi has no native approval ([approval.md](approval.md)), and the only interception point for tool calls is an extension's `tool_call` handler.

## Requirement map

| #   | Requirement                                                                                | Pi mechanism                                                                       | Status                                      |
| --- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------- |
| 1   | Model reviews risky operations using command, args and context                             | `tool_call` handler + `ctx.modelRegistry.streamSimple()` / `classify()`            | Supported                                   |
| 2   | Host binaries stay available; no blanket blocking by name                                  | Pi blocks nothing by default; per-call review only                                 | Supported (by design of the gate)           |
| 3   | Failure or inconclusive never equals authorization                                         | Thrown handler errors already block; everything else is up to the handler          | Partial                                     |
| 4   | Undecided goes to Pi's native approval                                                     | Pi has none; closest is `ctx.ui.confirm` / `select`, forwarded over RPC            | Unsupported as stated; substitute available |
| 5   | Off means full access                                                                      | Pi's default behaviour                                                             | Supported                                   |
| 6   | Reviewer: GPT-6 Luna when the Codex provider is active, else an economical available model | `ctx.modelRegistry` lookups; `gpt-6-luna` exists on `openai-codex` as a chat model | Supported with caveats                      |
| 7   | No undocumented internal endpoints                                                         | Use only Pi's public extension API and provider layer                              | Partial                                     |

### 1. Model-reviewed risky operations

- **Where it runs.** `pi.on("tool_call", handler)` receives `toolName`, `toolCallId`, `input` (for `bash`, the full command string; for `write`/`edit`, the path and content) and `parentToolCallId` for nested calls. Handlers are awaited before the tool runs, and one block ends dispatch ([types.ts L1193-L1265](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1193-L1265), [runner.ts L1249-L1268](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/runner.ts#L1249-L1268)).
- **Which calls.** Built-in tools, extension tools, MCP tools and calls from codemode scripts all pass through it ([mcp.md L252](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/mcp.md#L252), [extensions.md L261](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L261)). Not covered: the user's own `!`/`!!` commands (separate `user_bash` event) and code running inside extensions ([extensions.md L240](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L240)).
- **Context for the reviewer.** The handler context exposes `cwd`, `model`, `sessionManager` (read-only; `getBranch()` returns the active branch), `getSystemPrompt()`, `getContextUsage()`, `isIdle()` ([types.ts L326-L362](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L326-L362), [extensions.md L337-L355](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L337-L355)). HolyAgent's own Assignment data (ownership paths, constraints) would be passed to the extension by the host (flags, env, or a file), since Pi has no such concept.
- **Calling a reviewer model from an extension.** "Use `ctx.modelRegistry.streamSimple()` for provider-neutral nested model calls" ([extensions.md L327](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L327)). `ModelRegistry` also offers `complete`, `getAvailable`, `find`, `hasConfiguredAuth`, `getProviderAuthStatus` and `classify` ([model-registry.ts L64-L180](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-registry.ts#L64-L180)). Request options include `signal`, `reasoning`, `maxTokens`, `cacheRetention` and `sessionId` ([types.ts L251-L260, L377-L380](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/types.ts#L377-L380)).
- **Typed verdicts.** Classifier models answer `bool`/`choice`/`score` questions with probabilities, and `classify()` "never rejects" (returns `stopReason` and `errorMessage`) ([codemode.md L97-L131](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/codemode.md#L97-L131), [model-registry.ts L172-L180](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-registry.ts#L172-L180)). The shipped router example calls `ctx.modelRegistry.classify()` from an extension ([jev-router.ts L69](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/jev-router.ts#L69)).
- Gaps: Pi documents no place to add a handler's nested model usage to session totals (tools can report `usage` in their result; event handlers return no result of that kind) ([extensions.md L249](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L249)). Inference: record reviewer cost with `pi.appendEntry()` if HolyAgent needs it. Inference: reviewer input contains model-generated and possibly attacker-influenced text (file contents, command output are prompt-injection vectors per [security.md L5](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L5)), so the reviewer prompt must treat the operation and context as data, and a typed output schema is preferable to free text.

### 2. Host binaries stay available

Pi imposes no command allow/deny list: `bash` runs whatever the OS user can run ([security.md L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L3)). The official permission gate is a _name/pattern deny-list_ (`rm -rf`, `sudo`, `chmod 777`) ([permission-gate.ts L10-L33](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/permission-gate.ts#L10-L33)); that is the pattern HolyAgent must not copy. Do not use `--exclude-tools bash`, `--tools` allowlists that drop `bash`, or `shellCommandPrefix` tricks to implement the policy ([cli.md L119-L125](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L119-L125), [settings.md L143](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L143)). Inference: every call is reviewed on its content (command, args, working directory, target paths, whether it sends data out or deletes), and the reviewer's verdict, not the binary's name, decides.

### 3. Failure or inconclusive never equals authorization

- **Built in:** if a `tool_call` handler throws, Pi blocks the tool ([extensions.md L375](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L375), [agent-session.ts L658-L681](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/agent-session.ts#L658-L681)). Returning `undefined` means allow ([runner.ts L1249-L1268](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/runner.ts#L1249-L1268)). The docs say gate handlers should "fail closed" ([extensions.md L214](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L214)).
- **Not built in (Inference):** model errors, timeouts, empty or unparsable reviewer output and low-confidence classifier answers are _return values_, not exceptions. Provider streams end with `stopReason` `error` or `aborted` plus `errorMessage` rather than throwing ([custom-provider.md L202](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/custom-provider.md#L202)), and `classify()` never rejects. So the handler must treat every outcome except an explicit, schema-valid "allow" as not-allow, and must wrap its own reviewer call in a deadline using an `AbortSignal` (the docs describe no handler timeout). Dialogs: `confirm` resolves `false` on cancel or timeout ([rpc-extension-ui.md L186-L191](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/rpc-extension-ui.md#L186-L191)), which is deny.
- **Other ways around the gate (Inference):** handlers run in load order, so an earlier extension can mutate input first ([extensions.md L197](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L197)); a `pi` process started from `bash` is a new agent with its own extension set. Loading the gate as a user-level extension in the agent directory (not `.pi/`) means child Pi processes using the same agent dir also load it, and, Inference from security.md, user-level extensions are not gated by project trust because only `.pi` project resources are ([security.md L35-L45](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L35-L45), [security.md L63](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L63)). Pi also marks child processes with `AI_AGENT=pi` and `PI_CODING_AGENT=true`, which a reviewer could use as context ([environment-variables.md L11-L18](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/environment-variables.md#L11-L18)).

### 4. Undecided goes to Pi's native approval

Pi has no native tool approval to hand over to ([approval.md](approval.md)). What exists:

- `ctx.ui.confirm(title, message, { timeout, signal })` and `ctx.ui.select(...)`, available in the TUI and RPC (`ctx.hasUI`), not in print/JSON ([types.ts L149-L160, L323-L331](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L149-L160)).
- Over RPC the dialog arrives at the host as an `extension_ui_request` and the host replies with `extension_ui_response` ([rpc-extension-ui.md L5-L10, L48-L63](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/rpc-extension-ui.md#L5-L10)).
- Headless: the reference gate blocks when there is no UI ([permission-gate.ts L17-L23](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/permission-gate.ts#L17-L23)).

Inference: implement "undecided" as: UI available, then confirm (host-relayed under RPC, with a timeout that denies); no UI, then block. The `project_trust` event's `undecided` value is not a tool-approval path ([types.ts L705](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L705)).

### 5. Off means full access

Pi's default is exactly that: tools run with the process's permissions and nothing asks ([security.md L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L3)). Inference: `off` = the HolyAgent extension still loads (it carries the Assignment report tool) but its `tool_call` handler returns `undefined` immediately. The mode can be passed with an extension flag registered via `pi.registerFlag()` and read with `pi.getFlag()` ([types.ts L1692-L1708](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1692-L1708)) or an environment variable the host sets.

### 6. Reviewer model selection

What Pi offers for "GPT-6 Luna when the Codex provider is active" (details in [providers.md](providers.md)):

| Case                                                                  | Pi model                                                                                                         | How to detect                                                                                                                                                                                 | Call                                                                       |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| User is on the Codex subscription provider                            | `openai-codex/gpt-6-luna`, chat model, API `openai-codex-responses`, input $0.1 / output $0.5 per million tokens | `ctx.model?.provider === "openai-codex"`, or `ctx.modelRegistry.find("openai-codex", "gpt-6-luna")` plus `getProviderAuthStatus("openai-codex")` / `hasConfiguredAuth()`                      | `streamSimple()` with low `reasoning`, small `maxTokens`, JSON-only prompt |
| User signed in with ChatGPT on the `openai` provider                  | `openai/gpt-6-luna` chat model, `openai-responses` at `api.openai.com/v1`                                        | `find("openai", "gpt-6-luna")` + auth status                                                                                                                                                  | `streamSimple()`                                                           |
| User has `OPENAI_API_KEY` credentials on `openai` (not ChatGPT login) | `openai/gpt-6-luna` as a **classifier** via the Decisions API (typed `bool`/`choice`/`score`)                    | `getAvailableOfType("classifier", "openai")`                                                                                                                                                  | `classify()`                                                               |
| None of the above                                                     | the cheapest suitable available model                                                                            | `ctx.modelRegistry.getAvailable()` (models with working credentials; catalog entries carry `cost`, `reasoning`, `contextWindow`), or classifier models via `getAvailableOfType("classifier")` | `streamSimple()` / `classify()`                                            |

Sources: catalog entries ([openai-codex.json](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/data/openai-codex.json), [openai.json](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/data/openai.json)); the classifier is hidden under OAuth ([providers/openai.ts L26-L29](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/providers/openai.ts#L26-L29), [models.md L157](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L157)); registry methods ([model-registry.ts L64-L180](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-registry.ts#L64-L180)).

Caveats:

- The typed Decisions-API form of Luna, the best structured fit, is **not** available when the user is logged in through ChatGPT/Codex; there the reviewer is the chat model and HolyAgent must parse a JSON verdict itself.
- Choosing "economical" is a HolyAgent policy; Pi only supplies the data. Inference: rank available chat models by catalog `cost.input + cost.output`, require a minimum context window and `reasoning` support only if the reviewer prompt needs it, and prefer the active provider's cheapest model so no extra credentials are touched.
- Authentication for reviewer calls comes from the same `auth.json`/OAuth state as the main session; calls go through `ctx.modelRegistry`, which resolves credentials per request, so HolyAgent never handles tokens ([model-registry.ts L138-L180](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-registry.ts#L138-L180)).

### 7. No undocumented internal endpoints

- Use only the documented extension API (`ExtensionAPI`, `ExtensionContext`, `ctx.modelRegistry`) and published packages ([extensions.md](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md), [packages.md L76-L92](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L76-L92)). Do not read `auth.json`, call `getApiKeyForProvider`, run `pi auth print-api-key` / `print-bearer-token`, or hit provider URLs directly ([cli.md L293-L316](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L293-L316)).
- Endpoints used underneath, for the record: `openai` uses `https://api.openai.com/v1` (Responses; `POST /v1/decisions` for the classifier, which OpenAI documents: [Decisions guide](https://developers.openai.com/api/docs/guides/decisions)); `openai-codex` uses `https://chatgpt.com/backend-api`, which Pi labels "legacy" and neither Pi's docs nor the OpenAI page I read describes ([providers/openai-codex.ts L10-L11](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/providers/openai-codex.ts#L10-L11)). Status is Partial because HolyAgent can keep its _own_ calls to documented surfaces, but selecting the `openai-codex` reviewer means Pi itself talks to that backend. Decision for the user: if "no undocumented internal endpoints" is strict, prefer the `openai` provider (ChatGPT sign-in or API key) over `openai-codex` for the reviewer.

## Design sketch (Inference)

1. HolyAgent ships a Pi extension (loaded with `-e`, or installed at user level in a HolyAgent-managed agent directory) with: a `tool_call` gate, an `assignment_report` tool (`terminate: true`), a flag `--holyagent-auto` (`off` | `on`).
2. Gate algorithm for `auto = on`:
   1. Build the operation record: tool name, input, cwd, Assignment ownership paths, `parentToolCallId`, and a bounded slice of recent branch context.
   2. Fast paths that need no model: tools annotated read-only by their MCP server and Pi's own `read`/`grep`/`find`/`ls` against paths inside the working tree may be allowed without review only if HolyAgent decides so (policy, not Pi behaviour); anything else goes to the reviewer.
   3. Ask the reviewer for `{ verdict: "allow" | "deny" | "ask", reason }` (or the typed classifier equivalent). Run it under a deadline and an abort signal.
   4. `allow` only on an explicit, valid `allow`. `deny` blocks with the reason returned to the model. `ask`, malformed output, timeout, provider error, missing model: confirm through `ctx.ui.confirm` when `ctx.hasUI`, otherwise block.
   5. Record the decision with `pi.appendEntry("holyagent-review", ...)` for audit.
3. When `auto = off`, return `undefined` without review.

## Open questions for the HolyAgent owner

- Is "Codex provider active" defined as the selected model's provider being `openai-codex`, or any ChatGPT-subscription login (including `openai` with Sign in with ChatGPT)? The answer decides which `gpt-6-luna` entry is used.
- Is the legacy `openai-codex` backend acceptable under "no undocumented internal endpoints"?
- Should reviewer token cost be attributed to the Assignment? Pi gives no hook for it.
