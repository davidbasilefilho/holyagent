# Pi prompt caching, context compression, sub-agents and context reuse

**Status: planned for 0.3.0. The first two sections are the plan for the cache target and for compression; the sections after them are research on Pi's caching and sub-agents and are not shipped behaviour.**

Pi 1.4.0, commit `4a080252f06caf63a525d7873c5d94d3c23887e0` (the plan pins 1.5.0; see [README.md](README.md#version-risk)). Kimi facts are from the research of 2026-11-07. "Inference:" marks a conclusion drawn here, not a stated fact.

## Cache target

**Decided for 0.3.0 (maintainer):** the input-token cache hit rate targets 95% or more and aims for 98% or more. It is measured as cached input tokens over all input tokens, per session and per Assignment, and reported from the provider's usage data. Whether Kimi for Coding reaches 95% in HolyAgent's sessions is not known yet; the first sessions measure it.

How Kimi caches, from the sources:

- **Exact content prefixes.** The Kimi extension's measurements show a content-prefix hash aligned to 256-token chunks, with a time to live between 300 s and 1800 s. Cold `pi` runs do not share a cache ([docs/caching.md](https://github.com/Leechael/pi-provider-kimi-code/blob/main/docs/caching.md), third-party measurement).
- **Model and effort changes invalidate it.** Changing the model or the effort mid-session invalidates the context cache and forces a new prefill. Moonshot says to keep them fixed and to start a new session to change them ([Kimi Code models](https://www.kimi.com/code/docs/en/kimi-code/models)).
- **Cache keys are disputed.** Moonshot's Messages API reference says `metadata.user_id` improves the hit rate and that coding agents should set it to the session id ([reference](https://platform.kimi.ai/docs/api/messages)). Its Chat reference describes `prompt_cache_key` as required to improve the hit rate on the Kimi Code plan, as the Kimi Code maintainer 7Sageer quoted it on 2026-09-07 ([MoonshotAI/kimi-code#3506](https://github.com/MoonshotAI/kimi-code/issues/3506)). The extension's measurements contradict both: Kimi ignores `prompt_cache_key` and `cache_control`. The extension injects `prompt_cache_key` anyway, and `PI_CACHE_RETENTION=none` only skips that injection.
- **`PI_CACHE_RETENTION` does not extend Kimi's cache.** Moonshot's platform API has a 1 h option (`prompt_cache_options.ttl`, [context-caching guide](https://platform.kimi.ai/docs/guide/context-caching)); whether the Coding endpoint honors it is unknown, and the Kimi Code CLI has no setting for it ([kimi-code#3942](https://github.com/MoonshotAI/kimi-code/issues/3942)).
- **Pi's built-in provider**, if it is served over `openai-completions` (the built-in's API type is open, see [providers.md](providers.md#kimi-for-coding-global)), has no `prompt_cache_key` handling for `kimi-coding`: Pi's `promptCacheKeyMode` defaults to `auto`, which sends the key only to `api.openai.com`. Over `anthropic-messages` that inference does not hold, and the cache metadata differs (see the adapter table below). This is an inference from the provider file and docs; `openai-completions.ts` was not read.
- **Tools added mid-conversation** do not invalidate the cache on Kimi for Coding, per Pi's changelog ([pi-mono commit a3f265b](https://upd.dev/badlogic/pi-mono/commit/a3f265b1c6a49bc0904c76518d2d436ba44c95e9.diff)), which matters for the tools Billion Context injects.

What keeps the prefix stable, which the plan follows:

- **A byte-stable prefix.** Static material first, no dates or counters in instruction files, no mid-session roster change, and outputs kept compact ([claude-parity.md](claude-parity.md#6-skills-requirements-and-hooks)). The session context is added as a message, never by changing the system prompt ([claude-parity.md](claude-parity.md#6-skills-requirements-and-hooks)).
- **One model and one effort per session.** A role is launched on its row of the routing table and stays on it ([providers.md](providers.md#routing)).
- **One tool set per session, fixed at `session_start`.** Under T3 Code the extension deactivates T3's orchestration tools once, before the first request, and pins the kept T3 tools (HTML, browser preview and device) by name and the visual specialists' computer-use tools in the fixed set; it does not toggle tools mid-session. Pi's docs say a change of the active tools updates the prompt contributions and the provider tools, and models without mid-conversation system messages take a cache miss per change ([extensions](https://pi.dev/docs/latest/extensions), [t3-code.md](t3-code.md#t3s-tools-kept-and-deactivated)). The plan does not rely on the Kimi tolerance of tools added mid-conversation noted above.
- **Continuations reuse the session.** A warm specialist continues in the same session, within the 300 to 1800 s lifetime; a session reopened after that starts cold ([Sub-agents](#how-a-sub-agents-context-could-be-continued)).

## Context compression with Billion Context

**Decided for 0.3.0 (maintainer: "also billioncontext shall be installed"):**

- It is installed in the Pi integration only, not in the Claude plugin.
- The package is `billion-context` (the main package), pinned and moved only through `mise run deps:update` ([installation.md](installation.md#the-pin)).
- It is meant to compress the root and the specialists. Setup writes only the one setting its README gives, `{"pi":{"subagents":false}}`, which turns its own subagents off and keeps compression on ([extensions.md](extensions.md#settings-that-setup-writes)); no `delegate.forceEnable` is set. Whether the specialists that `@tintinweb/pi-subagents` starts are compressed too is to be verified with recorded fixtures before the pin is trusted.
- Its own `acp_delegate` subagent tools are off (`pi.subagents` false, set as `{"pi":{"subagents":false}}` in `~/.config/billion-context/billion-context.json`) (`@tintinweb/pi-subagents` runs the specialists, see [orchestration.md](orchestration.md#decision-for-030)).
- It is meant to replace Pi's compaction: the standalone `billion-context-pi` route cancels it, and the native `billion-context` route's behavior is to be verified (see below). HolyAgent itself registers no `session_before_compact` handler and sets no `autoCompactWindow` equivalent.

What the research found ([repository](https://github.com/ranxianglei/billion-context), [pi.dev page](https://pi.dev/packages/billion-context), [releases](https://github.com/ranxianglei/billion-context/releases), fetched 2026-11-07):

- **Pi support is direct.** Its manifest declares the extension `./dist/agent/pi-native.js`, and `pi install npm:billion-context` is the Pi route. v0.1.212 was published on 2 Nov 2026, MIT, 45.3 MB. The standalone `billion-context-pi` package ([README](https://github.com/ranxianglei/billion-context-pi)) is the other route and needs Pi 0.83 or newer. The two are mutually exclusive, because running both compresses twice.
- **Compaction.** The standalone extension cancels Pi's auto-compaction with `session_before_compact` returning cancel ([source](https://github.com/ranxianglei/billion-context-pi/blob/2c460050/src/index.ts)). The native route's behaviour was not confirmed.
- **It is young and fast.** The repository was created on 2026-08-06 and has 4333 stars and 884 open issues; releases landed on 31 Oct, 1 Nov and 2 Nov, roughly daily, and one maintainer wrote most of it. Hence the hard pin.
- **Subagent extensions.** With a subagent extension installed, its built-in delegate stands down at user or project scope (an older README said project scope only).
- **Runtime.** Node 20 or newer; the one native module, `sharp`, is optional.

Open points, to be settled before the pin is chosen:

- **Cache behaviour on Kimi for Coding is unknown.** The README claims a 95 to 97% prefix-cache hit rate and "prefix-cache friendly" compression; that is the project's own claim with no independent source. Compression that rewrites the prefix would work against the [cache target](#cache-target), so the measured rate decides.
- **Codemode compatibility is unknown**, and so is Windows support for the Pi route (the README gives Windows install steps but no support statement for Pi).
- **License.** The LICENSE on master is plain MIT (c) 2026 ranxianglei, and `package.json` says MIT, but GitHub's sidebar says "Other" and the v0.1.212 notes mention a pull request about removing AI restrictions. The terms may have changed recently, and an earlier attribution requirement was not re-checked against the commit history; check the LICENSE history before pinning ([LICENSE](https://github.com/ranxianglei/billion-context/blob/master/LICENSE)).

## Prompt caching in Pi

### Controls Pi exposes

- **Retention levels** are `none`, `short`, `long` in the provider layer ([model-schema.js in @earendil-works/pi-ai@1.4.0](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/model-schema.js), [types.ts L251](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/types.ts#L251)). Each adapter defaults to `short` and switches to `long` when the environment variable `PI_CACHE_RETENTION=long` is set (Anthropic 1h, OpenAI 24h per the env doc) ([environment-variables.md L88](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/environment-variables.md#L88), [anthropic-messages.ts L67-L90](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/api/anthropic-messages.ts#L67-L90), [openai-responses.ts L78-L90](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/api/openai-responses.ts#L78-L90)).
- The 1.4.0 `settings.md` has **no retention key**; only `cacheWarming` and `showCacheMissNotices` relate to caches ([settings.md L20-L23](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L20-L23)). `none` and per-request `cacheRetention` are reachable only through the pi-ai API or SDK options, not through `settings.json` (Inference: from the absence of such a key in the settings reference and in `settings-manager.ts`).
- **Session id as the affinity key.** The coding agent passes `sessionId: sessionManager.getSessionId()` into every request ([sdk.ts L427](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/sdk.ts#L427)). When retention is `none` the session id is not sent as a cache key ([openai-responses.ts L373](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/api/openai-responses.ts#L373), [anthropic-messages.ts L623](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/api/anthropic-messages.ts#L623)).
- **Model metadata** `promptCache: { short, long }` (seconds) declares a provider's best-effort cache lifetime; only tiers with a lifetime are eligible for warming ([models.md L104-L112](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L104-L112), [custom-provider.md L147](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/custom-provider.md#L147)).
- **Cache warming:** `cacheWarming` = `off` / `streaming` (default) / `idle`, global setting only. It runs only when the model declares a lifetime and Pi estimates at least $0.05 avoided cost; refresh usage counts toward session totals; extensions can override with the `cache_warming_decision` event ([settings.md L21-L23](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L21-L23), [extensions.md L234](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L234)).
- Summarization requests (compaction, branch summary) disable prompt-cache writes ([compaction.md L23](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/compaction.md#L23)).

Cache-friendly behaviours documented by Pi: changing prompt sections lets Pi append a transcript delta, while returning a full `systemPrompt` replaces the prompt ([extensions.md L216](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L216)); tool-set changes append to the transcript and can invalidate the prefix on providers that cannot express the change ([extensions.md L301](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L301)); a thinking-level change keeps the cache on GPT-6 with an API key but not with ChatGPT sign-in ([CHANGELOG.md L64-L71](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L64-L71), [models-configuration.md L156](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models-configuration.md#L156)); switching models between turns loses the prompt cache ([virtual-models.md L84](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/virtual-models.md#L84)).

Inference for HolyAgent: the session id is the cache key on most providers, so _reusing the same Pi session for the same Assignment_ is what preserves caching across continuations, while every fresh `pi` process with a new session id starts with a cold cache for its (identical) system prompt prefix on key-based providers. HolyAgent cannot set retention per Assignment through Pi's settings. `PI_CACHE_RETENTION=long` in the environment of a spawned Pi process helps on the Anthropic and OpenAI adapters, but it does not extend Kimi's cache (see [Cache target](#cache-target)), so the plan does not rely on it.

## Sub-agents

### Built in?

**Decided for 0.3.0:** specialists and workflows run through the `@tintinweb/pi-subagents` extension ([orchestration.md](orchestration.md#decision-for-030)). It replaces nicobailon's `pi-subagents` everywhere. The shipped example below is a source for launch flags only.

Pi itself has none. Pi "skips features like sub-agents and plan mode" and tells users to build or install them ([README L19](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/README.md#L19)); the 0.73.1 README adds "Spawn pi instances via tmux, or build your own with extensions" ([0.73.1 README L472](https://github.com/earendil-works/pi/blob/781152fc24841dc54b22284514604048ebe5e2c9/packages/coding-agent/README.md#L472)).

### Official example: `examples/extensions/subagent`

- A `subagent` tool with three modes: single `{ agent, task }`, parallel `{ tasks }` (max 8 tasks, 4 concurrent), chain `{ chain }` with a `{previous}` placeholder ([subagent/README.md L91-L97](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/README.md#L91-L97), [index.ts L34-L35](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/index.ts#L34-L35)).
- Each call spawns a separate `pi` process with `--mode json -p --no-session`, plus `--model`, `--tools` and `--append-system-prompt` from the agent definition ([index.ts L247-L260, L298-L344](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/index.ts#L298-L344)). Context is isolated per subagent and discarded afterwards (`--no-session`); the parent receives the final output, capped at 50 KB per parallel task ([subagent/README.md L5-L12, L112-L116](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/README.md#L5-L12)).
- Agents are Markdown files with YAML frontmatter (`name`, `description`, `tools`, `model`) under `~/.pi/agent/agents/` and, opt-in, project `.pi/agents/`; without `model` the subagent inherits the dispatcher's model and thinking level ([subagent/README.md L125-L151](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/README.md#L125-L151)). Project agents are repo-controlled prompts, so the example asks for confirmation unless the project is trusted ([subagent/README.md L55-L65](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/README.md#L55-L65)).
- Workflow prompts (`/implement`, `/scout-and-plan`, `/implement-and-review`) chain agents ([subagent/README.md L157-L163](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/subagent/README.md#L157-L163)).

It is a separate harness, not the `pi` CLI, and "the API changes without notice between releases" ([durable README L3](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/durable/README.md#L3)).

Compaction keeps long-lived sessions within the model window and leaves the original entries in the JSONL tree ([sessions.md L40-L46](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/sessions.md#L40-L46)).

Inference for HolyAgent: model an Assignment as one Pi session whose id is derived from the Assignment id (for example `--session-id <assignment-id>`), so a follow-up, a rework request or a resume after interruption becomes "same session, new prompt". That gives context reuse and a stable cache key without HolyAgent storing transcripts, and it contrasts with the shipped example, which deliberately throws the transcript away. The `--session-id` charset rule (letters, numbers, `.`, `_`, `-`, starting and ending alphanumeric) must be respected ([cli.md L92-L105](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L92-L105)).
