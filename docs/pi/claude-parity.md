# Claude parity: which HolyAgent Claude rules become Pi rules

Pi 1.4.0, commit `4a080252f06caf63a525d7873c5d94d3c23887e0`. The Claude side was read at commit `a4fa284` of branch `release/0.1.0/feat/claude-integration`: the instruction text in `packages/runtime/src/instructions/` (`claude-5.5/root.md`, `specialist.md`, `writing-bar.md`, `roles/`, `skills/`, `requirements/`), the plugin in `packages/integrations/claude/` (`hooks.json`, `src/agents.ts`, `src/workflows/`) and the CLI it calls (`cli/hook.ts`, `domain/plan.ts`, `domain/route.ts`). In the tables, a link in the Basis column is a Pi source; "Inference" marks a design choice of mine that no Pi document states. Section 1 holds the rules that cut across the rest, so later rows do not repeat them.

## Requirement

Binding, from the Intent (maintainer): "every Claude rule that Pi can carry (instruction, existing or custom extension) must become a Pi rule."

A rule counts as carried when the Pi agent receives the same text or Pi enforces the same behavior. Parity is judged per rule, not per mechanism: a Claude mechanism that exists only because of Claude Code (a permission prompt, a plugin manifest) is carried by what does the same job in Pi, or is listed under section 8 with the reason. Carriers:

- **Instruction**: text in a Pi system prompt, a Pi skill or a role prompt.
- **Existing**: a Pi built-in or a shipped example extension, loaded explicitly (examples are not loaded by default).
- **Custom**: an extension (or Pi package) HolyAgent writes.
- **Cannot**: Pi has no way to carry it; the reason is given.

## 4. Specialists

`specialist.md` and the role file are concatenated into each agent prompt, with `writing-bar.md` added for Worker.implementation and Reviewer.artifact (`agents.ts`). On Pi the same concatenation becomes the `--append-system-prompt` file of each spawned process, written by a Custom build step (section 7). Frontmatter fields map as in section 3: `tools` from the route's capabilities (Search to the web tool, Write to `write`/`edit`/`bash`, Shell to `bash`, Reviewer.code keeps `bash` for `git diff`), `model` and `effort` to `--model`/`--thinking`, `skills` to `--skill`, `cacheTtl` to the env var. Read-only roles are read-only only through their tool list in Claude, and the same allowlist does it in Pi. The description the root reads is built from the role's first sentence; the subagent tool's schema reuses it.

## 5. Workflows

The Claude plugin ships no workflow script: the root writes each one inline, with one `agent()` per entry `{id, agent, model, effort, prompt}` (its `agentType` is `holyagent:<agent>`), a pipeline by default and a review stage after its writers. The `plan` command says how to run the Ready work, with a `fallback` of direct subagents and, beside it, `continues` for work that resumes a warm specialist.

## 6. Skills, requirements and hooks
