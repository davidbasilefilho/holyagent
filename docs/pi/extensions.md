# Pi extensions and packages

**Status: planned for 0.3.0. The first two sections are the plan; the sections after them are research on Pi's extension API and are not shipped behaviour.**

The Pi facts below are for Pi 1.4.0 (commit `4a080252f06caf63a525d7873c5d94d3c23887e0`); the plan pins 1.5.0 (see [README.md](README.md#version-risk)). Paths below are relative to `packages/coding-agent/` unless a link says otherwise. Statements marked "Inference:" are conclusions drawn here, not Pi's.

## The HolyAgent package

The Pi integration will be one Pi package, built from the same instruction sources as the Claude plugin:

- **Where and how it is generated.** A new folder `packages/integrations/pi/` sits beside `packages/integrations/claude/` and reuses the runtime's domain, state, CLI and instructions without copying them. A second generator reads the same instruction sources as the Claude build and writes the Pi package. Its paths join the generated-path list, so the existing byte-for-byte sync check covers them; every generated file carries a note naming its source; `mise run build` syncs the version from the root `package.json`. A sync test for the Pi output is modelled on the Claude plugin's.
- **Ship format: built JavaScript.** The maintainer's words: "built js, use bun build". The extension is bundled with `bun build` into the generated package, not shipped as TypeScript for Pi to transpile.
- **Layout.** The conventional `extensions/`, `skills/` and `prompts/` directories or a `pi` key in `package.json`, with the `pi-package` keyword ([Pi packages](#pi-packages)).
- **Host modules are peer dependencies with the range `"*"`.** Pi 1.5.0's package docs require this for `@earendil-works/pi-ai`, `pi-agent-core`, `pi-coding-agent`, `pi-tui` and `typebox`. `scripts/dependency-ranges.test.ts` accepts only caret ranges today, so it gains an exception for Pi peer dependencies.
- **Paths stay within 120 characters**, the limit `scripts/repo-paths.test.ts` enforces.
- **The extension itself** is a default-exported factory that starts no process, socket, watcher or timer; it does that in `session_start` and releases it in an idempotent `session_shutdown` ([Events and hooks](#events-and-hooks)). Its handlers do not build Claude-style hook payloads: they run the CLI through the package's wrapper and build the context with the runtime's own context builders ([the extension entry](#the-extension-entry)). It works in TUI, RPC, JSON and print modes and fails closed.
- **It ships two skills**, `dev-server` and `user-busy`, in the Agent Skills format, and the `code-review` and `security-review` prompt templates ([claude-parity.md](claude-parity.md#6-skills-requirements-and-hooks)).

## The extension entry

**Status: built.** The Pi extension of the package, `extensions/holyagent.js`, gives every Pi session its role and its HolyAgent context. The launcher (the root's system prompt, per-role prompt files, the specialist launcher), the tool surface, the Kimi provider, `setup` and `doctor` are later changes.

- **The factory** registers the `--holyagent-role` flag and four handlers (`session_start`, `session_compact`, `before_agent_start`, `session_shutdown`) and starts nothing. Pi parses flags after the factory runs, so the role is read in the handlers.
- **Roles.** `root` (the default, so plain `pi` starts the HolyAgent root) gets the status; its root rules reach the system prompt through the launcher. `specialist` (a child the root launches) gets the status and neither the root rules nor the reminder. `session` (any other session) gets the core of the root rules, in the Kimi family's words, with `${HOLYAGENT_PI_ROOT}` filled in with the package folder, then the status. Any other value fails closed: one notice that names the flag and the three roles, and nothing else.
- **What runs.** `session_start` (startup, reload, new, resume, fork) and `session_compact` run `holyagent status`, and a resume and a compaction then run `holyagent reconcile`, one after the other. All of a collection's commands share one deadline of ten seconds, the Claude hook's timeout, and each is also limited to eight; the config and the state folder are asked together, since neither needs the other. A compaction that starts while an older collection is still running stops it, and a shutdown stops the one in flight; the result of a stopped collection is dropped. The result is not a system-prompt change, which would cost the cache: it is a custom message that the next run takes from `before_agent_start`, once. `session_shutdown` stops the commands still running and releases the session, and it waits for every command the session started, older aborted gathers included, up to the 2 s stop grace each; calling it again does nothing.
- **Budget and silence.** The context is built by the runtime's session context builder, so it has the Claude hook's character budget (`CONTEXT_BUDGET`) and the same narrowing of the status. A project with no `.holyagent` state folder gets nothing, except that a `session` role still gets the core, as the Claude hook gives it to a main thread that is not the root. In a git work tree the folder is the one `holyagent state mode` reports, checked after `status`, which makes the state worktree of a project that keeps state. A project that is not a git repository keeps its state in its own `.holyagent` folder, as the Claude hook finds it, so the extension checks that folder and does not ask `state mode`, which fails there.
- **The wrapper.** Pi runs the extension under Node, and the runtime reads files with Bun, so the extension reaches the runtime only through `scripts/holyagent` of the package (run with `sh`), generated from the Claude plugin's wrapper with the same empty Bun config, beside `scripts/holyagent.js`. The bundle is the CLI plus two things of its own: `config <state-folder>...`, which loads the HolyAgent config through the runtime loader and prints it as JSON, and a leading `--project <folder>`, which makes the folder the working directory before the command runs. Under Pi, Bun therefore starts in the package's folder and enters the project in-process through `--project`, after its own startup, so the project's `.env` and `bunfig.toml` are never read; the Claude hook starts the same wrapper in the project itself, which is why the wrapper passes no env file and an empty config. The extension starts every program, `sh` and `git`, in the package's own folder and names the project in the arguments (`--project`, `git -C`), because on Windows a bare program name is looked up in the working directory first, where a project could put its own `sh` or `git`.
- **Config.** `pi.enable: false` makes the extension register no more than its flag and handlers and add no context. An invalid config file stops it with the loader's message, which names the file and the field.
- **Failure.** A failing command, a timeout or output it cannot read adds one line to the next run (`holyagent: ...`) and never throws into Pi. The handlers use no TUI-only API, only `ctx.cwd`, `pi.exec` and the message result, so TUI, RPC, JSON and print modes behave the same.
- **Not covered yet.** `HOLYAGENT_HOST=pi` and `HOLYAGENT_WORKFLOWS` are not set (`pi.exec` takes no environment, so the launcher sets them on the Pi process), and the requirements of the Intent in use are not added after a resume or compaction. `piContext` also leaves out three notices the Claude hook adds: the legacy-state notice (a project with `.holyclaude` or `.holycodex` state and no `.holyagent` folder), the cloud identity text, and the setup notice.

**The rpiv packages under T3 Code.** T3 renders only the RPC dialogs (`select`, `confirm`, `input`, `editor`), `notify` and `setStatus`; `custom()` returns `undefined` in RPC mode, and `hasUI` is true there, so `@juicesharp/rpiv-ask-user-question` does not remove its tool as it does with no UI. Inference: a tool that depends on `custom()` TUI rendering does nothing under T3. Whether either package uses `custom()` is to be verified; where one does, a HolyAgent adapter maps it to the dialogs and status ([t3-code.md](t3-code.md#dialogs-and-status-only)).

Not loaded: the `protected-paths.ts` and `permission-gate.ts` examples (no gate in 0.3.0, see [auto-mode.md](auto-mode.md)) and the experimental `pi-durable` package. The shipped `todo.ts`, `question.ts` and `questionnaire.ts` examples are no longer the carriers; whether the examples in Pi's tarball can be referenced from a package at all is unknown, since the docs do not say.

### Web tools

- **Default with Kimi:** `moonshot_search` and `moonshot_fetch`, two optional Moonshot-side tools of `pi-provider-kimi-code`. They are off by default; how they get enabled is not stated in the research and is to be settled when the package is built. They need the OAuth login, so a user who logs in with `KIMI_API_KEY` cannot use them and `pi-web-kit` stays the fallback for that case. They send queries and URLs to Moonshot's services. The tools are listed in the extension's [README](https://github.com/Leechael/pi-provider-kimi-code). Moonshot itself says its web search is being updated and is not recommended for production workflows for now (reported by the 2026-11-07 research, no page linked), which is why `pi-web-kit` stays as the fallback.
- **`pi-web-kit`** gives `web_search` and `web_fetch`, with Exa among its providers; its `web_search` requires a `purpose` parameter for Exa ([page](https://pi.dev/packages/pi-web-kit), undated, scraped 2026-11-07; its maintenance status is unverified beyond the listing). It is disabled when the provider extension offers web tools, and it stays selectable in `config.json` as the fallback.
- Other maintained candidates the research found, not chosen: `pi-web-access`, `@zhcsyncer/pi-search-hub`, and any MCP server through Pi's built-in MCP.
- The Claude `WebSearch` and `WebFetch` of the Librarian roles map to these tools ([claude-parity.md](claude-parity.md#3-claude-tools-the-instruction-text-names-and-what-carries-each)).

## What an extension is

An extension is a TypeScript module that exports a default factory receiving `ExtensionAPI`. The factory may be async, and Pi waits for it before continuing startup ([extensions.md L13-L36](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L13-L36), [extensions.md L54-L58](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L54-L58)). Extensions run inside the Pi process with its OS permissions and can inspect prompts, tool calls, files, credentials and session history ([extensions.md L3-L5](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L3-L5)).

## How extensions load

- **Transpilation:** Pi uses `jiti`, so local `.ts` files need no build step ([extensions.md L38](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L38), [loader.ts L570-L584](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/loader.ts#L570-L584)).
- **Locations:** `<agent-dir>/extensions/` (default agent dir `~/.pi/agent`) and project `.pi/extensions/`. Pi loads direct `.ts`/`.js` files and subdirectories containing `index.ts`/`index.js` ([extensions.md L44-L48](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L44-L48), [configuration.md L7-L37](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/configuration.md#L7-L37)). Extra paths come from the `extensions` setting ([settings.md L148-L163](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L148-L163)).
- **CLI:** `-e/--extension <path>` loads a file, directory or built-in (repeatable); `-ne/--no-extensions` disables discovered, configured and built-in extensions but explicit `-e` still loads ([cli.md L186-L196](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L186-L196)).
- **Project trust:** project extensions in `.pi/extensions` load only after the folder is trusted. Only personal and explicit command-line extensions can handle the `project_trust` event ([security.md L35-L55](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L35-L55), [extensions.md L50](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L50)).
- **Built-in extensions:** `builtin:mcp`, `builtin:llama.cpp`, `builtin:codemode`, `builtin:tool-search` load by default and can be disabled with `-builtin:<name>` in the `extensions` setting ([settings.md L163](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/settings.md#L163)).
- **Lifecycle rules:** do not start processes, sockets, watchers or timers in the factory, because some invocations load extensions without starting a session. Start them in `session_start` and release them in an idempotent `session_shutdown` ([extensions.md L58-L60](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L58-L60)). `/reload` replaces the whole extension runtime ([extensions.md L50](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L50)).
- **SDK embedding:** in the SDK, extensions are passed as inline factories through `DefaultResourceLoader`; SDK sessions do not include the built-in codemode/tool-search/MCP extensions unless the host adds `createCodemodeExtension()` etc. ([sdk.md L110-L118](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/sdk.md#L110-L118)).

## Events and hooks

Per-prompt order: `input`, `before_agent_start`, `agent_start`, then per turn `turn_start`, model-request hooks, tool hooks, `turn_end`, then `agent_end`, `agent_before_settle`, `agent_settled`. A model request runs `context`, `context_with_system`, `before_provider_headers`, `before_provider_request`, `after_provider_response`, `provider_stream_event`. Each tool call runs `tool_execution_start`, `tool_call`, `tool_execution_update`, `tool_result`, `tool_execution_end` ([extensions.md L62-L125](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L62-L125)). Session events: `project_trust`, `session_start`, `session_before_switch`, `session_before_fork`, `session_shutdown`, `resources_discover` ([extensions.md L127-L145](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L127-L145)). `agent_end` is not a final-idle signal; `agent_settled` is ([extensions.md L145](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L145)).

How handler results compose ([extensions.md L203-L215](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L203-L215)):

| Pattern                       | Events                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------- |
| Notification (return ignored) | most lifecycle events                                                                              |
| In-place mutation             | `tool_call.input`, `before_provider_headers.headers`, `before_agent_start.systemPromptOptions`     |
| Chained transformation        | `input`, `context`, `context_with_system`, `message_end`, `tool_result`, `before_provider_request` |
| Gate                          | handled `input`, blocked `tool_call`, cancelled session operation, handled `user_bash`             |
| Actionable boundary           | `turn_end`, `agent_before_settle` (can add entries and return `continue: true`)                    |

Gate handlers "should fail closed when their safety decision cannot be made" ([extensions.md L214](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L214)). Handlers run in extension load order ([extensions.md L197](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L197)). Tool calls from one assistant message can run in parallel, so handlers must not assume sibling calls exist ([extensions.md L236-L238](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L236-L238)).

`tool_call` (the interception point used by [approval.md](approval.md)): the event carries `toolName`, `toolCallId`, `input` and optional `parentToolCallId`; the handler may mutate `event.input` or return `{ block, reason, terminate }` ([types.ts L1193-L1265](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1193-L1265), [types.ts L1454-L1463](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1454-L1463)). The runner stops at the first handler that blocks ([runner.ts L1249-L1268](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/runner.ts#L1249-L1268)).

Other events useful to an orchestrator: `model_select`, `thinking_level_select`, `message_end`, `tool_result` (redact or replace output), `before_provider_request` (change the serialized payload), `cache_warming_decision` ([types.ts L1597-L1664](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/extensions/types.ts#L1597-L1664), [extensions.md L234](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L234)).

## Custom tools

- A tool has a `name`, model-facing `description`, a TypeBox `parameters` schema and `execute()`. The result needs `content` and a `details` field. Throw to signal failure; returning an object does not mark an error ([extensions.md L245-L253](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L245-L253)).
- `terminate: true` ends the agent loop after the tool batch without an extra model turn, only if every tool in the batch agrees ([extensions.md L253](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L253), [structured-output.ts L1-L45](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/examples/extensions/structured-output.ts#L1-L45)).
- `outputSchema` plus `structuredContent` return machine-readable results to programmatic callers such as codemode scripts ([extensions.md L259](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L259)).
- Nested model calls inside a tool should report `usage` so session totals stay right; file-mutating tools should use `withFileMutationQueue()` ([extensions.md L247-L257](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L247-L257)).
- `ctx.executeTool(name, args)` lets a tool call other tools. Nested calls pass through validation and the `tool_call`/`tool_result` handlers and carry `parentToolCallId` ([extensions.md L261](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L261)).
- **Exposure** (`direct`, `model-only`, `codemode`, `deferred`, `hidden`) decides whether the model sees a tool, scripts can call it, or both. Tools cannot be unregistered, only re-registered as `hidden` ([extensions.md L265-L277](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L265-L277)).
- **Annotations** (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) follow MCP semantics; MCP tools carry their server's hints; hints are not verified ([extensions.md L279-L291](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L279-L291)).
- Active tool sets can change at runtime with `pi.setActiveTools()`. Pi records the change in the transcript, and providers that cannot represent the transition get a full checkpoint, which can invalidate the cached prefix ([extensions.md L297-L301](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L297-L301)).

## Pi packages

- A package is a directory or npm package with conventional `extensions/`, `skills/`, `prompts/`, `themes/` directories or a `pi` key in `package.json`; the `pi-package` keyword makes it discoverable in the gallery ([packages.md L42-L74](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L42-L74)).
- Sources: `npm:`, `git:`, an `https://` git URL, or a local path. Versioned npm specs and git tags/commits are pinned ([packages.md L29-L40](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L29-L40)).
- Commands: `pi install|remove|uninstall|update|list|config`; personal installs are recorded in `~/.pi/agent/settings.json`, `-l/--local` writes `.pi/settings.json` (read only after trust); `-e <source>` tries a package for one run ([packages.md L7-L27](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L7-L27), [cli.md L250-L291](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L250-L291)).
- Host-provided modules (`@earendil-works/pi-ai`, `pi-agent-core`, `pi-coding-agent`, `pi-tui`, `typebox`) must be `peerDependencies` with `"*"` and not bundled ([packages.md L76-L92](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L76-L92)).
- Packages can execute extension code and include skills that instruct the model to run programs; the docs tell users to review third-party source first ([packages.md L21](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L21)). Package resources can be filtered per type with `!pattern`, `+path`, `-path` ([packages.md L94-L121](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L94-L121)).

## Inference for HolyAgent

- Inference: delivering HolyAgent as one Pi package makes the version pin explicit, because Pi pins git tags and commits ([packages.md L29-L40](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/packages.md#L29-L40)). The plan uses a git tag source, not `npm:` ([installation.md](installation.md#how-holyagent-installs)).
- Inference: project-level `.pi/extensions` need trust, and trust prompts cannot show in print, JSON or RPC mode (see [configuration.md](configuration.md#project-trust)). The plan documents the user-level install first, so its loading does not depend on a prompt, and children inherit the parent's project trust: `--approve` only when the parent trusted the project ([installation.md](installation.md#global-and-project-local-installs)). Sourced: only personal and command-line extensions can handle `project_trust` ([security.md L63](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L63)).
