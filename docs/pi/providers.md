# Pi providers and models

Pi 1.4.0, commit `4a080252f06caf63a525d7873c5d94d3c23887e0`. "Inference:" marks my own conclusions.

## Provider model in one paragraph

A _provider_ is the service/account, a _model_ is what it serves. Users connect with `/login` (OAuth or API key, stored in `auth.json`) or with environment variables, then pick a model with `/model` ([models.md L5-L35](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L5-L35), [providers.md L10-L18](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/providers.md#L10-L18)). Pi ships a bundled model catalog and overlays newer data from pi.dev; `pi update --models` forces a refresh ([models.md L15](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L15)). The catalog is also browsable at [pi.dev/models](https://pi.dev/models).

## Is `gpt-6-luna` (GPT-6 Luna) there?

**Yes.** What the 1.4.0 source says, exactly:

1. **`openai-codex` / chat model `gpt-6-luna`**, name "GPT-6 Luna", API `openai-codex-responses`, base `https://chatgpt.com/backend-api`, reasoning true, input text and image, context 272000, max output 128000, price per million tokens: input 0.1, output 0.5, cache read 0.01, cache write 0.125 (a higher tier above 272000 input tokens) ([openai-codex.json](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/data/openai-codex.json), key `chat:gpt-6-luna`). A sibling `gpt-5.6-luna` also exists (different id, higher price).
2. **`openai` / chat model `gpt-6-luna`**, API `openai-responses`, base `https://api.openai.com/v1`, same prices; it is listed for API-key use and, since the OAuth provider only filters classifier models, also for Sign in with ChatGPT (Inference from the filter code: only classifier models are removed under OAuth) ([openai.json](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/data/openai.json), key `chat:gpt-6-luna`; [providers/openai.ts L26-L29](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/providers/openai.ts#L26-L29)).
3. **`openai` / classifier model `gpt-6-luna`**, API `openai-decisions`, context 922000, input price 0.1, no output price ([openai.json](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/data/openai.json), key `classifier:gpt-6-luna`). It calls OpenAI's Decisions API, `POST /v1/decisions` ([openai-decisions.ts L19-L20, L175](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/api/openai-decisions.ts#L19-L20)). Pi's doc: "OpenAI's Decisions API needs an API key. Sign in with ChatGPT credentials do not work with it, so `gpt-6-luna` is not listed as available while `openai` is logged in through `/login`, even when `OPENAI_API_KEY` is set; log out of `openai` to use the key" ([models.md L157](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L157)). The code comment says the same: "Sign in with ChatGPT tokens only reach the Responses API; the Decisions API rejects them" ([providers/openai.ts L27-L29](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/providers/openai.ts#L27-L29)).
4. The model also appears under `azure`, `github-copilot`, `opencode`, `opencode-go`, `cloudflare-ai-gateway`, `radius`, `vercel-ai-gateway`, `amazon-bedrock` (as `openai.gpt-6-luna` variants) and `openrouter` (`openai/gpt-6-luna` plus `-pro`, `:batch`) ([same catalog directory, e.g. github-copilot.json](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/data/github-copilot.json)).
5. It is documented as a classifier by OpenAI: "Send requests to `POST /v1/decisions` using `gpt-6-luna`, the only currently supported model" ([OpenAI Decisions guide](https://developers.openai.com/api/docs/guides/decisions)). Pi's changelog introduced it in 1.1.0 ([CHANGELOG.md L175-L184](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L175-L184)) and Luna chat support earlier, in 0.87.1 ([CHANGELOG.md L511-L517](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/CHANGELOG.md#L511-L517)).
6. Pi's own docs example for scripts uses it: `models.getModelOfType("classifier", "openai", "gpt-6-luna")` ([codemode.md L171](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/codemode.md#L171)).

Configurability: any model id can also be added or overridden by hand in `models.json` (`models` adds or replaces; `modelOverrides` changes metadata of built-in models) ([models.md L45-L75](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L45-L75), [models-configuration.md](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models-configuration.md)). The catalog is data, not code, so a newer `gpt-6-luna` entry can arrive without a Pi upgrade ([models.md L15](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L15)).

Inference: for a "reviewer = GPT-6 Luna when the Codex provider is active" rule, the matching Pi identity is chat model `openai-codex/gpt-6-luna` (subscription, ChatGPT backend), or `openai/gpt-6-luna` as a chat model when the user signed in with ChatGPT on the `openai` provider. The typed `openai/gpt-6-luna` classifier is **not** reachable from a ChatGPT login, only from `OPENAI_API_KEY`. See [auto-mode.md](auto-mode.md).

Endpoint caution: Pi's docs do not describe `https://chatgpt.com/backend-api`, and the provider that uses it is labelled "legacy" in source ([providers/openai-codex.ts L10-L11](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/providers/openai-codex.ts#L10-L11)). Whether OpenAI documents that endpoint for third parties is not answered by anything I read. The newer `openai` route sends the ChatGPT-derived token to `https://api.openai.com/v1` ([oauth/openai-chatgpt.ts L19-L26](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/ai/src/auth/oauth/openai-chatgpt.ts#L19-L26)), the public API host used for API keys. HolyAgent should reach models only through Pi's provider layer and never call these URLs itself.

## Classifier and image models (non-chat)

Classifier models answer typed questions about JSON state (bool, choice, score) with probabilities. Built in: TypeSafe Jev, Cloudflare Clef variants, and OpenAI `gpt-6-luna` ([models.md L142-L157](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L142-L157)). They are not in `/model`; scripts reach them through `codemode`, and extensions through `ctx.modelRegistry.classify()` ([models.md L159, L184](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L159)). `classify` never rejects and returns `stopReason` plus `errorMessage` on failure ([model-registry.ts L172-L180](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-registry.ts#L172-L180)). Image models are similar ([models.md L186-L203](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L186-L203)).

## Selecting models from a host

- CLI: `--provider`, `--model <pattern>` (exact id, fuzzy match, `provider/id`, optional `:<thinking>` suffix), `--thinking off|minimal|low|medium|high|xhigh|max`, `--models` (cycling scope), `--list-models [search]`; thinking is clamped to what the model supports ([cli.md L55-L76](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L55-L76)).
- Readiness probe: `pi auth check --provider <id> --json` prints `ready`, `not_ready` or `invalid` with exit code 0/1/2 and can refresh OAuth tokens ([cli.md L293-L316](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L293-L316)). `pi auth print-api-key` / `print-bearer-token` print secrets to stdout; HolyAgent should not use them.
- RPC: `get_available_models`, `set_model`, `set_thinking_level` ([rpc-commands.md L208-L330](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/rpc-commands.md#L208-L330)).
- Extension / SDK: `ctx.modelRegistry.getAvailable()`, `find(provider, id)`, `hasConfiguredAuth()`, `getProviderAuthStatus()`, `streamSimple()`, `complete()`, `classify()` ([model-registry.ts L64-L180](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-registry.ts#L64-L180)). Extensions may make nested model calls with `ctx.modelRegistry.streamSimple()` ([extensions.md L327](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L327)).
- Custom endpoints: `models.json` for OpenAI-, Anthropic- or Google-compatible APIs; `pi.registerProvider()` for custom APIs/OAuth; `pi.registerVirtualModel()` for a model that routes each request to a physical model ([models.md L45-L60](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/models.md#L45-L60), [custom-provider.md](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/custom-provider.md), [virtual-models.md L1-L30](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/virtual-models.md#L1-L30)).

Inference: HolyAgent's per-Assignment "model/effort" maps one to one to `--model <provider/id>:<thinking>` (or `set_model` + `set_thinking_level` in RPC). Pi's thinking scale (`off` to `max`) is a superset of coarse effort names, but the mapping from HolyAgent effort values to Pi levels is a HolyAgent decision. Inference: Pi's catalog is the source of truth for which model ids exist per user, so HolyAgent should validate role-to-model choices at launch with `--list-models` or `getAvailable()` rather than hard-coding ids.
