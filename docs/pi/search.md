# The find and grep tools on fff

**Status: ships in 0.3.1 as the `fff` capability (`pi.features.fff`, on by default).** Pi's `find` and `grep` tools, for the root and specialists, are replaced by [fff](https://github.com/dmtrKovalenko/fff) through its Pi package `@ff-labs/pi-fff` (0.11.0, MIT), an in-process Rust file finder reached through a Node binding: no `fd` or `rg` process per call, a background index, frecency ranking and a fuzzy `find`. The Claude plugin is not affected: it keeps `holyagent-cli rg` and `holyagent-cli fd`, which run the ripgrep and fd the user installs ([decisions.md](../decisions.md)).

## The decisions

- **Override mode (Intent default, revisitable).** The package has three modes, and setup puts it in `override`: its tools then take the names of Pi's own `grep` and `find` (and add `multi_grep`), so the tool surface of every role, the instruction text that names `grep` and `find`, and the agent files' `tools:` lines stay as they are. The default mode, `tools-and-ui`, adds `fffind`, `ffgrep` and `fff-multi-grep` beside Pi's tools, which would leave two search tools per role.
- **Setup writes only missing settings.** The global `pi-fff.json` lives in `~/.pi/agent` or `PI_CODING_AGENT_DIR`. The package does not read a project copy, so project and local setup skip this file. User-scope setup adds missing `mode: "override"` and `enableHomeDirScanning: false`. Existing values stay. Turning FFF off or running `holyagent setup --undo` removes only unchanged values that setup recorded writing.
- **Projects under home keep FFF search.** The home setting applies to a session started at the home directory itself, not a project or worktree beneath it. At home, pi-fff skips its index and leaves Pi's built-in `find` and `grep` available when using override mode. HolyAgent does not pick another directory or start a recursive fallback. Open Pi in the intended project before searching it.
- **Native overrides still apply.** pi-fff checks its command-line flag first, then the environment, then the settings file. For mode, use `--fff-mode` or `PI_FFF_MODE`. To opt in to indexing home, set `enableHomeDirScanning: true`, pass `--fff-enable-home-scan`, or set `FFF_ENABLE_HOME_SCAN=1`. To disable it for a run, omit the flag and set `FFF_ENABLE_HOME_SCAN=0`. Pi 1.5.0 treats the flag as enabled even when written as `--fff-enable-home-scan=false`. The separate `warnOnHomeDirScan` setting only controls the warning when indexing is enabled at home. Setup leaves it unchanged.
- **Directory links are followed.** Setup leaves `followSymlinks` unset, so the package indexes through directory symlinks by its own default (for worktree and stow layouts). Pi's own `rg` and `fd` do not follow them, so a link inside a repository to a folder outside it (`docs -> ~/.ssh`) becomes searchable under a workspace path. A user who wants the index kept inside the real tree sets `followSymlinks: false` in `pi-fff.json` (setup keeps it), or `--fff-follow-symlinks` or `FFF_FOLLOW_SYMLINKS` per run. Version 0.3.1 wrote `followSymlinks: false`; the next setup takes it out by its record, only while it still holds that value, and a `followSymlinks` the user set stays, so someone who wants links left unfollowed after upgrading from 0.3.1 sets `followSymlinks: false` again by hand after that upgrade setup run.
- **Every role prefers FFF in codemode when enabled and available.** The root activates the registered FFF tools, and specialist allowlists include the extension tools as well as the replacement `grep` and `find` names. Override mode exposes `grep`, `find` and `multi_grep`; other modes expose `ffgrep`, `fffind` and `fff-multi-grep`. Discover them with codemode and read their schemas. When FFF is disabled or not offered on the host, specialists use their built-in `find` and `grep` through codemode; the root uses shell `rg` and `fd`, or system `grep` and `find` if those are unavailable. Report unexpectedly missing or failing FFF tools as a setup problem.
- **Where the native library has no build, the capability is off.** `@ff-labs/fff-node` ships its library for darwin (arm64, x64), linux (arm64, x64, each glibc and musl), win32 (arm64, x64) and android (arm64). On any other host the capability is not offered, in either form: setup loads no package and writes no setting, doctor prints `~ pi capability fff: not offered ... (its native library does not cover <host>, only ...)` and fails nothing, and Pi keeps its own `find` and `grep`. A supported host whose library failed to install is not detected: the package reports the failed start as an error when the session starts, and its tools then return errors.

## Switching it

`holyagent setup --fff on|off` writes `pi.features.fff` to the config of the scope and installs or removes `@ff-labs/pi-fff` in the same run, like any other capability ([configuration.md](configuration.md#capabilities)); `off` leaves Pi's own `find` and `grep` in place. The capability has both forms, with the same package, and needs nothing of the system. `holyagent doctor` prints `pi capability fff` with its package at its pin, and a `~ tool settings` line naming any missing managed keys in `pi-fff.json`. An explicit home scanning preference is not missing.

## What the package does

Read from the [pi-fff 0.11.0 source](https://github.com/dmtrKovalenko/fff/tree/95fd777c2529fc7b4d7572dabff64cc07268f2c5/packages/pi-fff) and its `@ff-labs/fff-node@0.11.0` dependency:

- In `override` mode it registers `grep`, `find` and `multi_grep`. A session started from `$HOME` or `/` that the package's config opts out of indexing keeps the `ffgrep` and `fffind` names, so Pi's built-ins stay reachable there. The upstream default is to index `$HOME` with a warning when no option overrides it. HolyAgent setup supplies the opt-out above.
- It keeps two LMDB databases (frecency and query history) under `~/.pi/agent/fff/`, or reuses an fff.nvim database if one exists.
- Not confirmed: whether each specialist, which runs as an in-process child session, starts its own index, and whether a late registration after the initial active-tool selection is visible before a reload.
