# Browser and desktop controls by setup target

Browser automation, access to an existing browser profile and desktop control are separate. Installing a HolyAgent profile does not grant permission for any of them.

| Setup target               | Browser                                                                                                                                                                                                                                                                       | Desktop and devices                                                                                                                                                            |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Pi in T3 Code              | T3 Preview for the in-app browser. A separate **Browser Use** page configures OpenCode Browse on graphical hosts. You can mark several detected browsers. Setup reviews each selected profile and runs supported pairings one at a time without changing browser preferences. | Official Cua Driver for assigned graphical visual specialists. T3 Device Simulator is separate and needs the SDK on the T3 environment host.                                   |
| Native Codex CLI           | No desktop In-App Browser or ChatGPT browser extension connection. The CLI can explicitly register a separate external MCP server such as [OpenCode Browse](https://github.com/anomalyco/browse).                                                                             | The CLI setup provisions a dedicated Codex profile and its HolyAgent plugin. It does not provision the desktop app's Computer Use or change its permissions.                   |
| ChatGPT desktop with Codex | **Codex In-App Browser** uses its own profile through `@Browser`. The **ChatGPT browser extension** connects an existing local profile and is a separate optional handoff.                                                                                                    | The desktop app owns **Computer Use**. Enable it through its own Settings or plugin prompts, then grant OS and per-app permissions there.                                      |
| Claude Code CLI            | Claude in Chrome is an Anthropic integration, separate from OpenCode Browse. Use `claude --chrome` for a session or manage it with `/chrome`. [OpenCode Browse](https://github.com/anomalyco/browse) is also a separate optional MCP server.                                  | Anthropic documents native CLI `computer-use` on macOS only. Enable it per project in `/mcp` and grant the requested macOS permissions. HolyAgent does not make these changes. |
| Claude Code desktop        | The Browser pane uses a clean profile. Claude in Chrome can use the existing profile.                                                                                                                                                                                         | Native desktop computer use is documented for macOS and Windows. Manage it in the app.                                                                                         |

The [Codex browser](https://learn.chatgpt.com/docs/browser), [ChatGPT browser extension](https://learn.chatgpt.com/docs/chrome-extension), [Codex Computer Use](https://developers.openai.com/codex/computer-use), [Claude in Chrome](https://code.claude.com/docs/en/chrome), [Claude Computer Use](https://code.claude.com/docs/en/computer-use), and [T3 devices](https://github.com/pingdotgg/t3code/blob/main/docs/user/devices.md) guides explain where their own approvals apply.

## Interactive browser choices

- In graphical Pi setup, open **Browser Use**, then **Browsers** to mark the detected candidates you want. **Done** keeps the list. **Back** at the picker discards unconfirmed changes. The setup reports unsupported or unverified installations without assuming that they work. Pass `--browser-executable <absolute-path>` to include a portable candidate that was not detected. The path is checked without launching it.
- OpenCode Browse needs its extension and a separate pairing for each browser profile. **Configure** is preselected when Browser Use is enabled and a setup action is available. Choose **Skip** to leave the current pairing alone. Choosing a row, moving focus, and leaving a page do not run Browse. The reviewed pairings only start after Apply and after closing the setup screen. OpenCode Browse issues a distinct one-time code for each reviewed profile. Setup shows installation or enablement instructions for unready profiles instead of claiming that they are paired. When the relay already holds pairings, its profile keys do not identify a local browser folder, so setup keeps them and shows how to verify or add a missing pairing without replacing a known one. Dry-run and unattended setup never start pairing.
- Run `holyagent setup codex` in a terminal, or select Codex in combined setup. Desktop-native browser entries appear only when an eligible local desktop installation is detected. The named command stays line-based with `--dry-run`, `--form headless` or `--non-interactive`. In **ChatGPT browser extension**, select **Install in** next to a supported detected browser. After you review, apply and close setup, HolyAgent opens OpenAI's guide in that exact browser. An unsupported browser is listed with a reason but has no install button. Finish in ChatGPT desktop under **Settings > Computer Use** and follow its plugin, extension and permission prompts. Opening the guide does not install, pair or authorize anything.
- Official documentation lists Chrome, Edge, Brave, Opera and Vivaldi for the ChatGPT browser extension on supported desktop builds. Opera lacks side chat. The Linux desktop preview documents Chrome browser actions. Availability depends on the desktop release, workspace policy and rollout. A Codex CLI feature flag is not proof that a desktop connection exists.

## Managed setup conflicts

Interactive setup lists any managed conflicts it can safely resolve before applying the joint plan. **Apply and replace conflicts** is preselected, but nothing is replaced until you confirm it. **Keep current files** updates the review to show which affected targets will be skipped. You can still apply the other targets or cancel the whole plan. If a reviewed file changed, review again before applying.

- For Pi, setup can replace a recognized HolyAgent package registration in the selected scope and preserves its filters. The result reports a `.holyagent-package.*.bak` next to that scope's settings file. This is a backup of one registration entry, not the settings file. To undo the replacement, locate the new `source` in the Pi `packages` array and replace just that entry with `entry` from the backup. If the native install fails and only the old entry disappeared, setup restores that entry without reinstalling or verifying its package files. If the package list also changed, setup keeps the backup and leaves the list as it found it. Review any additional edits or duplicate matches before restoring manually.
- For Codex, only receipt-backed root, HolyAgent workflow and provably instruction-only role edits are eligible in the dedicated profile. Setup reports the backups for each replaced file under `CODEX_HOME/holyagent/setup-backups`. You can copy a backup over its matching file after checking for newer edits. Unowned files, settings, policy options and opt-outs are not replaced. If manual changes affect ownership or policy, keep the files or choose a separate profile instead.

## Compatibility evidence

On 26 November 2026, the official stable releases checked were [Codex CLI 0.172.0](https://github.com/openai/codex/releases/tag/rust-v0.172.0), [Claude Code 2.1.332](https://www.npmjs.com/package/@anthropic-ai/claude-code/v/2.1.332) and [OpenCode Browse 0.1.5](https://www.npmjs.com/package/@opencode/browse/v/0.1.5). The official desktop changelog reports [Codex app 26.1120](https://learn.chatgpt.com/docs/changelog) on 23 November. CLI versions and native MCP commands were checked with the Linux binaries. The desktop rows reflect upstream support and local detection, not a signed-in desktop test.

The historical [HolyCodex 0.16.12 installer](https://github.com/davidbasilefilho/holycodex/blob/a56aa726c39347e610d1e2430ac49ab4ef62aad6/packages/cli/src/installer.ts#L148-L189) left `browser@openai-bundled` to the desktop lifecycle. Its [optional selections](https://github.com/davidbasilefilho/holycodex/blob/a56aa726c39347e610d1e2430ac49ab4ef62aad6/docs/CONFIGURATION.md#optional-capabilities) kept desktop control separate. The archived [HolyClaude plugin](https://github.com/davidbasilefilho/holyclaude/tree/bb3fe56e00425e99746650b002a73241bcd37f51/plugin) did not install a browser or computer-use transport. Its [root instructions](https://github.com/davidbasilefilho/holyclaude/blob/bb3fe56e00425e99746650b002a73241bcd37f51/plugin/agents/holyclaude.md#L153) used T3 preview tools and the host's native computer tools only when available. HolyAgent preserves those boundaries without porting the historical installers.
