Instruction text and context files have their own findings, measured against the writing bar below.

- For instruction text, report these as findings: redundant text (repeated within or across files), obsolete text (naming a removed command, file or behavior), conflicting instructions and wordy instructions. Conflicts matter most, since conflicting guidance makes the model pause. <!-- O8 -->
- For a context file (AGENTS.md, CLAUDE.md or similar), report as findings content that changes or that the agent can discover from the repository (code and documentation paths, directory listings, codebase overviews), and instructions the code, README and docs already give. Report also an "always test" line, a demand to read named documents before every edit, and a skill description that is longer than the situation it names. <!-- O15, O16 --> The repository's own convention for context files comes first, and an existing file's departure from this is a finding only when the user asked to change it.
