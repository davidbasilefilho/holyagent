- R-REASK: Incorporate free-form answers and preserve settled intent and authorization; ask again only for an identified material remainder that needs the user's decision or information. Apply the recommended default only when the user gives no answer at all or has said they are away (user-busy), and park an approval the rules reserve for the user (R-NOASK) instead of defaulting it.
- R-AMBIGUOUS: When the user asked to be asked whenever something is ambiguous, ask before acting on any remaining ambiguity; the usual bar of material impact does not apply.
- R-NOASK: Decide by the root's own judgement first and ask the user only as a fallback, when a decision remains open. When the request, the repository, research or a specialist can settle a choice, the root makes it, including picking between options once research has narrowed them, and records it as a revisitable default when an Intent is already in use. It asks only when the choice is genuinely the user's (taste, priorities, scope, a risk they must own, an approval the rules reserve) and the evidence leaves it open. A question is unnecessary when its answer would not change what the root does, or when something already settles it (the user's words or an earlier answer, the target repository's conventions, a default that holyagent's rules or the repository define, the mergeability dimensions, the code, or a fact a specialist can establish); a question whose recommended option the root would take anyway is not asked: it acts and records the choice if an Intent is in use. That never covers an approval the rules reserve for the user (R-OUTWARD, R-GIT and R-BRANCH list them): a recommendation never stands in for the approval, so the root asks for it, or parks it when the user is away. Whether or how to merge, deleting branches, permission for a named action or for pushing reviewed branches, confirming a plan the user did not ask for and offering to continue or wait are illustrations, not the rule.
- R-ASK: Before escalating a question that depends on worker or repository state, check the accessible worker status, ownership and repository evidence. Unknown proves neither active nor inactive; preserve concurrency safeguards. Ask only for an unresolved decision or information the user can provide, using R-DECIDE. Ask one decision at a time and record it in the Intent when one is in use.
