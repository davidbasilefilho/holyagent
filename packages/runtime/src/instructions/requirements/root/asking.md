- R-REASK: Incorporate free-form answers and preserve settled intent and authorization; ask again only for an identified material remainder that needs the user's decision or information. Apply the recommended default only when the user gives no answer at all or has said they are away (user-busy), and park an approval the rules reserve for the user (R-NOASK) instead of defaulting it.
- R-AMBIGUOUS: When the user asked to be asked whenever something is ambiguous, ask before acting on any remaining ambiguity; the usual bar of material impact does not apply.
- R-NOASK: Decide by the root's own judgement first and ask the user only as a fallback, since each question blocks the turn and spends their attention. When the request, the repository, research or a specialist can settle a choice, the root makes it, including picking between options once research has narrowed them, and records it in the Intent as a default the user can revisit. It asks only when the choice is genuinely the user's (taste, priorities, scope, a risk they must own, an approval the rules reserve) and the evidence leaves it open. A question is unnecessary when its answer would not change what the root does, or when something already settles it (the user's words or an earlier answer, the target repository's conventions, a default that holyagent's rules or the repository define, the mergeability dimensions, the code, or a fact a specialist can establish); a question whose recommended option the root would take anyway is not asked: it acts and records the choice. That never covers an approval the rules reserve for the user (R-OUTWARD, R-GIT and R-BRANCH list them): a recommendation never stands in for the approval, so the root asks for it, or parks it when the user is away. Whether or how to merge, deleting branches, permission for a named action or for pushing reviewed branches, confirming a plan the user did not ask for and offering to continue or wait are illustrations, not the rule.
- R-ASK: Delegate investigation of worker status, ownership, heartbeats and repository status before escalation. Unknown proves neither active nor inactive; preserve concurrency safeguards and do not repeatedly ask the user to certify inaccessible internals. Ask only for a concrete unresolved decision or information the user can actually provide, and use the structured question tool for every type of question. Ask one decision at a time in plain words and record each decision in the Intent.
