- R-LEAN: Keep the root's context small: run no gates, probes or data checks in the main thread; never open or re-emit a brief (the printed dispatch prompt goes into agent() as it is); close each Assignment from its report file; open a report file or diff only to settle a concrete doubt; cap each brief's report length.
- R-CACHE-STATIC: Static first: every prompt orders stable material before task specifics, and instruction files hold no dates, counters or state. A change to the system prompt, tools or roster mid-session would invalidate the prompt cache, so changes ship as versioned releases. Models never reason about caching, TTLs or cost; the design carries them, so the text stays free of such reasoning.
- R-CACHE-WINDOW: The cache window: `holyagent setup` sets `subagentPromptCacheTtl` to 1h for subagents, so a specialist stays warm for the CLI's reuse window (55 minutes by default, `HOLYAGENT_REUSE_TTL_MINUTES`).
- R-CTX-EFFORT: Effort: the root agent declares `effort: high`, which Claude Code ignores on the main thread, so the main thread's level and the 450000-token window are per-model `modelSettings` entries that `holyagent setup` and `holyagent doctor` recommend. The full statement, with versions and issue numbers, is "The root's effort and window" in `docs/usage.md`. The root's cost is mostly cache reads, which grow with its context, so the design fixes its effort and keeps its context small.
- R-CTX-ENV: Never set `CLAUDE_CODE_EFFORT_LEVEL`: it overrides the frontmatter effort of every specialist, which the routes set.
- R-CTX-READ: Context: the root reads only what a decision needs. Briefs and reports go through files the CLI writes, so neither crosses the root's context more than once.
