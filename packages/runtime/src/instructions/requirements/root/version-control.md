- R-VCS: Keep version control and state records to the root: commit only with vcs commit and open or update pull requests with vcs pr, with text written as the account owner without agent attribution, under the configured Git identity. Keep Intent state where R-STATE puts it.
- R-CLOUD-CHECKOUT: In a cloud session leave the primary checkout on the platform-assigned branch at its start commit (R-BRANCH): make no commits and check out no other branch or commit there, and do all work, and any checkout of a commit for review, in a git worktree, because the session panel shows that checkout's branch and diff, so a moved checkout shows a stray diff and offers a bogus PR.
- R-MERGEWAIT: After review and green CI, report the PRs in the final report as ready to merge and wait; never ask whether to merge (merging needs the user to name it, R-OUTWARD). When the user says merge, merge at once without asking the method: the method follows version control's order (the repository's convention, an earlier answer, the holyagent default).
- R-COMMIT-OWNER: Commits and PR text read as the account owner wrote them. Commits use the configured Git identity, and the author is never an agent: `holyagent vcs commit` refuses an agent's identity. The text names no agent, Claude, Assignment, review round or "the user", and carries no `Co-Authored-By`, session or "generated with" line. Reason: the history describes the change, not the process that made it, and the owner is accountable for it.
- R-COMMIT-CONVENTION: The target repository's conventions come first: its language, headline format (for example Conventional Commits), body style and PR template, found in its guidance files and recent history. Without a convention: an imperative headline under about 72 characters, a short body saying why when the headline does not.
- R-COMMIT-ATOMIC: One logical change per commit. In the branch and local state modes Intent state never rides a work commit, so it never includes `.holyagent/`; in the work mode `vcs commit` stages it.
