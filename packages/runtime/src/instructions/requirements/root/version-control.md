- R-VCS: Keep version control and state records to the root: use the commit workflow for the current harness and open or update pull requests with vcs pr. In the harness that otherwise attributes commits to its agent, require the identity-checking commit wrapper both locally and on the web; only its web sessions need separate author setup. Other harnesses use plain Git. In every harness follow R-COMMIT-OWNER and R-COMMIT-ATOMIC. Keep Intent state where R-STATE puts it.
- R-CLOUD-CHECKOUT: In a cloud session leave the primary checkout on the platform-assigned branch at its start commit (R-BRANCH): make no commits and check out no other branch or commit there, and do all work, and any checkout of a commit for review, in a git worktree, because the session panel shows that checkout's branch and diff, so a moved checkout shows a stray diff and offers a bogus PR.
- R-MERGEWAIT: Call a PR merge-ready only once independent review, applicable gates and the repository's merge requirements hold for its current head. Merge only with authorization (R-OUTWARD), including authorization already granted for this action. Recheck the head and required approvals and checks before merging by the configured path. Keep an unready PR unmerged and identify the blocker. Choose the method by repository convention, then user choice, then the HolyAgent default.
- R-COMMIT-OWNER: Commits and PR text read as the account owner wrote them. Commits use the configured Git identity, and the author is never an agent; if the configured identity is missing or belongs to an agent, report the blocker. The text names no agent, Claude, Assignment, review round or "the user", and carries no `Co-Authored-By`, session or "generated with" line. Reason: the history describes the change, not the process that made it, and the owner is accountable for it.
- R-COMMIT-CONVENTION: The target repository's conventions come first: its language, headline format (for example Conventional Commits), body style and PR template, found in its guidance files and recent history. Without a convention: an imperative headline under about 72 characters, a short body saying why when the headline does not.
- R-COMMIT-ATOMIC: One logical change per commit. Stage only the exact paths for authorized direct edits or accepted Assignments and check the staged diff for unrelated changes. In the branch and local state modes Intent state never rides a work commit, so it never includes `.holyagent/`; in work mode stage only the relevant changed Intent files, excluding ignored `.holyagent/local/`.
