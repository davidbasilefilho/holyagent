- R-HILLCLIMB-BASELINE: For iterative improvement, define the outcome, one primary metric or explicit qualitative criterion, and a meaningful gain threshold. Set applicable correctness, security and accessibility guardrails. Use the smallest reproducible baseline, record its conditions and evidence, and establish ordinary variation when the result is noisy.
- R-HILLCLIMB-TRIAL: Choose a concrete hypothesis and the smallest reversible trial. Isolate one variable when it clarifies what caused a change. Recheck guardrails and compare the candidate under the same conditions with the best verified result, keeping the original baseline. Keep only a supported improvement; undo only the rejected trial's changes and leave unrelated work intact.
- R-HILLCLIMB-STOP: Continue useful trials autonomously inside the authorized scope. Stop at the target, when further trials have no meaningful gain, when evidence cannot settle the result, or when progress needs a material user decision or approval. Report the baseline, best verified result, observed change and uncertainty, and any remaining decision.
- R-HILLCLIMB-VISUAL: For visual trials, compare equivalent captures at the same viewport, state and interaction input. Inspect contrast, alignment, readability and relevant accessibility or interaction. Use the brief and applied design criteria for original visuals when no target image exists. Explain material qualitative judgments; a pixel difference alone does not establish improvement.
- R-HILLCLIMB-SCENARIOS: State the testable hypothesis before measuring. Choose representative scenarios and scale the checks to the change's impact. Compare relevant before/after behavior through the real entry point with the version and conditions recorded. Separate installation from use. For defensive and operational changes, use isolated harmless fixtures, exercise relevant failures and recovery, and check that permissions, existing state and data remain protected. For experience changes, exercise the actual user or developer flow as well as applicable visual and accessibility checks.
- R-HILLCLIMB-EVIDENCE: For material changes, record the hypothesis, exact baseline and candidate revisions, commands, samples and keep/revert decision, including rejected trials. Check that the treatment ran. Use a negative control where useful to show that a check catches the fault or that activation is observable. Alternate run order when it can bias a comparison and report the sample count and variation. Separate correctness from a measured gain. Do not claim live activation from setup or a version check.
- R-HILLCLIMB-REUSE: Use relevant existing visual judging, platform design, render setup, performance measurement and evidence guidance where available. Keep the iteration method in this skill and leave specialist checklists and acceptance rules to their owners.
